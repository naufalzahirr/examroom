# Batas keamanan ExamRoom

ExamRoom mengendalikan browser di dalam aplikasi, bukan seluruh perangkat pada semua konfigurasi Android.

- **Lock Task terkelola** memerlukan aplikasi diizinkan oleh device owner / DPC. Guru dapat mewajibkannya per sesi; aplikasi memeriksa dukungan dan mode aktual, lalu menunggu persetujuan backend sebelum memuat WebView.
- **Screen Pinning** memerlukan persetujuan Android dan dapat dilepas melalui mekanisme sistem. Tidak setara kiosk penuh. Mode pinned diterima untuk seluruh ujian; pengaturan wajib mode terkelola telah dihapus. Jika lock terlepas atau aplikasi meninggalkan layar, browser ditutupi/dijeda dan memerlukan kode lanjut khusus ujian untuk melanjutkan. Screen Pinning tetap memerlukan pengujian pada OEM dan versi Android sasaran.
- `FLAG_SECURE` diaktifkan pada jendela aplikasi dan dialog. Ini tidak menjamin perlindungan dari root, OS yang dimodifikasi, kamera eksternal, keyboard/overlay tidak tepercaya atau penghapusan data/uninstall. Tidak ada klaim mencegah seluruh kecurangan.
- Status mode yang dikirim ke server berasal dari aplikasi peserta; **bukan remote hardware attestation**. Klien yang dimodifikasi pada perangkat tidak tepercaya dapat memalsukan telemetri. Server tetap mengisolasi akun, memvalidasi kode, waktu/status sesi, token, PIN dan transisi resume. Gunakan perangkat terkelola untuk kebutuhan kepercayaan lebih tinggi.
- API hanya menerima HTTPS pada build publik. WebView menolak sertifikat TLS bermasalah, HTTP, file/content access, mixed content, unduhan, unggah berkas dan izin kamera/mikrofon/lokasi. Resource yang diizinkan tidak otomatis memberi izin navigasi utama. URL langsung Forms terikat ke ID formulir sejak awal; tautan pendek diresolusikan melalui redirect HTTPS yang diizinkan saat pemeriksaan perangkat, kemudian browser dimulai dari dokumen Forms yang ditemukan. Resource interception bukan firewall semua koneksi Android/WebSocket.
- Keluar dan melanjutkan menggunakan kode enam angka yang berbeda untuk setiap ujian. Kode dibuat otomatis menggunakan generator acak kriptografis, diverifikasi dengan hash, dan disimpan terenkripsi agar guru pemilik ujian dapat melihatnya. Respons publik/siswa dan daftar ujian tidak memuat kode atau hash. Hanya respons guru pada create/detail/reactivate yang memuat `action_codes`.
- Pembatasan percobaan salah berlaku per ujian dan per tindakan (exit/resume), dibagi antartoken peserta. Otorisasi resume berlaku satu menit dan tidak dapat diganti dengan transisi checking. Kode keluar tidak bisa dipakai melanjutkan dan sebaliknya. PIN global profil versi lama tidak lagi dipakai untuk otorisasi ujian.
- Aktivasi ulang sesi kedaluwarsa/nonaktif mengganti kode masuk dan masa berlakunya dalam transaksi; peserta, waktu mulai, dan kode pengawas tetap. Pengaktifan ulang tidak mereset durasi peserta. Sesi yang masih aktif menolak permintaan penggantian kode.
- Android menyimpan kandidat pemulihan setelah keluar pada Android Keystore-backed vault. Kembali ke ujian memerlukan kode lanjut dan persetujuan penguncian lagi; jam ujian tetap berjalan selama keluar. Jawaban tetap mengikuti penyimpanan/pengiriman Google Forms, bukan database ExamRoom.
- Migrasi `2026_10_27_000001_exam_action_codes` membuat kode berbeda untuk sesi existing dan menghapus syarat mode terkelola. Pertahankan APP_KEY karena mengenkripsi identitas serta kode pengawas.
- Durasi dibatasi waktu monotonic perangkat dan waktu server. Pada versi ini masa berlaku kode juga diperiksa saat sesi hendak aktif/kembali aktif dan heartbeat; sesi dengan kode kedaluwarsa dijeda. Atur masa berlaku kode cukup untuk keseluruhan jadwal ujian.
- Identitas peserta minimal nama dan nomor, terenkripsi menggunakan Laravel APP_KEY di database. Token peserta di server berupa SHA-256 hash; token Android dienkripsi dengan kunci Android Keystore. Tidak ada identitas siswa sebagai akun pengguna atau token guru yang dibagikan ke peserta.
- Pemantauan menunjukkan status terakhir yang dilaporkan, bukan bukti kehadiran saat ini atau anti-manipulasi. Peserta yang putus jaringan dapat memiliki status lama; waktu pembaruan terakhir ditampilkan. Jumlah peserta menghitung rekaman bergabung, termasuk jika orang yang sama mengulang alur, bukan jumlah identitas unik yang diverifikasi.
- Jawaban, nilai dan konfirmasi kirim tetap milik Google Forms. ExamRoom tidak menganggap tap tombol kirim, URL tertentu, maupun keluarnya siswa sebagai bukti jawaban terkirim. Form yang mewajibkan SSO tertentu dapat menolak embedded WebView. Form yang memerlukan upload/kamera tidak didukung pada versi ini.
- Tidak ada verifikasi institusi. Dua guru yang mengisi nama sekolah identik tetap terpisah berdasarkan user ID. Pergantian profil tidak mengubah identitas sesi lama.
- Web menyimpan bearer token hanya dalam memori halaman; refresh membutuhkan login kembali. Gunakan HTTPS, proteksi hosting, SMTP sungguhan, retensi/scheduler aktif dan konfigurasi OAuth resmi sebelum penggunaan publik.

Rujukan: [Android Lock Task](https://developer.android.com/work/dpc/dedicated-devices/lock-task-mode), [Credential Manager](https://developer.android.com/identity/sign-in/credential-manager-siwg), [Laravel Authentication](https://laravel.com/docs/12.x/authentication).
